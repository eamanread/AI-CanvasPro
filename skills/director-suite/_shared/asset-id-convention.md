# 资产ID 与一致性约定（asset_id Convention · 制片圣经与分镜的"焊点"）

> 本文件是**全套件 asset_id 的单一权威来源**。角色表/场景表/道具表/分镜表一律以此为准；任何表的 §1 命名说明若与本文件冲突，以本文件为准。
> 作用：让"谁/在哪/用什么"在四张表里指向**同一个 ID**，使分镜表"连续性锁定"能逐项引用上游表的硬锚，跨镜不漂从结构上被保证。

---

## 1. asset_id 命名规范（全片唯一）

| 类型 | 格式 | 例 | 定义于 |
|---|---|---|---|
| 角色 Character | `[Element_<Name>]` | `[Element_LinChen]`、`[Element_ZhaoShanhe]` | 角色表 |
| 群像集合 Group | `[Element_<GroupName>]` 作单一集合实体 | `[Element_ThreeElders]`（三前辈） | 角色表 |
| 场景 Scene | `[Element_<Space>_<Tag>]`（同物理空间多状态共享 `<Space>` 根、用 `<Tag>` 区分） | `[Element_PrivateRoom_Warm]` / `[Element_PrivateRoom_Cold]` | 场景表 |
| 道具 Prop | `[Prop_<Name>_<NN>]`（两位序号，同款多件按件编号） | `[Prop_Ashtray_01]`、`[Prop_FoldingKnife_01]` | 道具表 |
| 音色 Voice | `[Voice_<Name>]`（与角色一一对应，单列以便配音复用） | `[Voice_LinChen]` | 角色表 §音色 |

**规则**：
- ID 用拼音/英文 PascalCase，全片唯一、无同物异名；一旦分配，所有表与文件名锁死不改。
- 角色与场景共用 `Element_` 前缀（类型由上下文字段区分：`出场角色:` vs `场景:`）；道具用 `Prop_`、音色用 `Voice_`，便于一眼辨型。
- 同一物理空间的不同时段/陈设/冷暖状态：**共享 `<Space>` 根**、用 `<Tag>` 或 `StateN` 区分，并在场景表「状态/Look」字段显式声明承接，**不得**拆成互不相干的两个实体（否则地标对不上）。
- **同角色多 Look（造型/年龄/受伤态）= 主 ID + 状态后缀**，血缘指向同一主 ID：`[Element_LinChen]`（基准）→ `[Element_LinChen_Suit]` / `[Element_LinChen_Wounded]`；各 Look 外观可独立生成（首图为基准、后续 ImageToImage 续），但审计能追回"是同一个人"。
- **道具状态用 `@sN` 节点引用**：同一件道具的状态轴节点用 `[Prop_Tea_01]@s1(冒热气)` / `@s2(无热气)` / `@s3(已收走)`，分镜引用须引到**具体状态节点**而非只引道具名（详见道具表「状态变化轴」）。
- **ID 精确匹配**：占位符/引用处的 ID 必须与注册 ID **完全一致**（大小写/拼写漂移如 `[element_linchen]`、`[Element_Linchen]` 视为穿帮）。**先绑后生**：用户已提供素材直接绑定为该 ID 的 asset、不重复生成。

## 2. 一致性等级 L1 / L2（每条锚定项逐项标）

| 等级 | 含义 | 下游行为 |
|---|---|---|
| **L1 硬锚（不可变）** | 跨全片永不改变的物理事实 | 分镜「连续性锁定」直接锁死、逐项继承；改动即穿帮废稿 |
| **L2 随剧情可变（须显式声明）** | 允许随叙事改变，但**每次变化必须沿表里登记的"变化轴/状态节点"发生**，且在分镜「连续性锁定」写明"承上组×××／本组起×××" | 不得静默漂移；变化点留痕、可追溯 |

> 铁律：**没有"默认可变"。未标 L2 的一律按 L1 锁死。** L2 道具的变化只能落在道具表"状态变化轴"已登记的节点上；分镜里出现未登记的突变 = 连续性破口。

---

## 3. 参考图绑定（喂模型）

- 每个 asset_id 可绑定一张/一组参考图，喂 Seedance/图像模型时用占位符绑定：`<<<image_1>>>=@[Element_LinChen]`、`<<<image_2>>>=@[Element_PrivateRoom_Warm]`、`<<<image_3>>>=@[Prop_FoldingKnife_01]`。
- 用户已上传的角色/场景/道具图：**直接绑定为该条目的 asset_id、不重复生成**；描述须与该图匹配不矛盾。
- 视觉资产由下游成员生成：角色→`character-board`（多视图设定板）、场景→`color-palette`/场景四视图、道具→道具图；它们都以本 asset_id 命名产出，回挂到对应表。
- **场景图/道具图不渲人物、不渲文字水印Logo**（人物身份由角色表锁定；剧情必需的可读文字用引号写进字段，不靠图上文字承载）。

## 4. 四表交叉引用写法

| 在哪张表 | 字段 | 引用谁 |
|---|---|---|
| 角色表 | 出现场景 / 随身道具 / 对手戏 / 出现镜头组 | `[Element_<Space>_<Tag>]` / `[Prop_*]` / `[Element_<Name>]` / 组号 |
| 场景表 | 出场角色 / 关联道具 / 出现镜头组 | `[Element_<Name>]` / `[Prop_*]` / 组号 |
| 道具表 | 归属角色 owner / 出现场景 / 出现镜头 | `[Element_<Name>]` / `[Element_<Space>_<Tag>]` / 镜号 |
| 分镜表 | 镜头组「场景」字段 + 各镜「连续性锁定」 | 逐项引 `[Element_*]` / `[Prop_*]`（**不重述外观，只引 ID**） |

双向可查：上游表登记"出现镜头组"，分镜定稿后回填，形成闭环；改某个 L2 项时可由此定位所有受影响镜头。

---

## 5. 一致性回检清单（内部跑，绝不写进成片）

1. **引用闭合**：分镜每个 `[Element_*]/[Prop_*]/[Voice_*]` 都在上游表里存在。
2. **覆盖完整**：上游表每个 L1/焦点实体都至少被一个镜头用到（未用到的降级或删）。
3. **道具状态轴一致**：分镜中每件 L2 道具的状态推进，逐镜落在道具表已登记的状态节点上，无未登记突变（如上镜满杯、下镜空杯却无饮用动作）。
4. **跨镜跨组锚点一致**：造型/音色/主光色温/光位 跨镜不漂；所有 L2 变化都已在分镜显式声明承接。
5. **命名一致**：四表 asset_id 前缀与本文件一致（角色/场景 `Element_`、道具 `Prop_`、音色 `Voice_`）。

> 与各表契约同纪律：本清单只在内部跑，**不得**作为"自检确认✓"之类脚注写进任何成片表——那本身就是引擎泄漏。
