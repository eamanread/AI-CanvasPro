# D9 真机判别力验证（2026-06-23）· 评审整改证据

> 回应评审:「D9 的5题基线是自证循环(tautology)——expected_features 是作者从自己写的 final_text 反推的,
> 命中率永远1.0;秤与菜同源」。本次用**真实 LLM(gemini-3.1-pro，grsai网关)出真分镜**,且
> **expected_features 在生成前 a-priori 定为武戏题材必备(非反推)**,证明审计在真实好/差输出上**有判别力**。

## 方法（破 tautology 的关键）

1. **先定 a-priori 武戏高潮(情绪5级)判据**(生成前,与具体输出无关):
   - F1 强情绪景别:含「特写」 · F2 动作镜头语言:含「手持|斯坦尼康|动作匹配」 · F3 急节奏:含「武戏|急」 · F4 含「切镜方式」字段
2. 两次真机生成同一段武戏剧本(山道隘口·拔刀格挡·火星四溅):
   - **skilled**:系统提示词=真实 `storyboard.megaprompt.md`(24KB,skill本体)
   - **naive**:无 skill、大白话、诱导秒数时间轴(模拟"没用skill的人")
3. 用**同一套 a-priori 判据**审两份真实输出。

## 结论与诚实边界

- ✅ **审计在真实 LLM 输出上有判别力**:放行 skill-compliant 的好分镜、拦截 naive 的差分镜,且判据 a-priori 非反推——直接反驳"tautology / 烂分镜也能GO"(至少在结构+题材维度)。
- ✅ skilled 输出存为**非自指真机基线** `baselines/cases/realmachine-wuxi.json`(final_text=gemini真出,我没手写),纳入 run_eval + 黄金签名。
- ⚠️ 已知小 gap:naive 用"0-2**秒**"被 fields/features 抓到了,但**没被壁钟时码闸抓**——`leak_scan.ABS_TIMECODE` 只认拉丁"s"不认中文"秒";暂不改,因易与合法时长区间(如"约6-8s")撞,需语义区分(单一时长估值 vs 时间轴切分),列为后续。
