# 《制片圣经》总控 Skill 设计蓝图

> 一句话定位：把"读完剧本→脑子里那套只有资深制片才有的隐性盘算"固化成一条可执行流水线，让剧本进、**四张互锁的圣经表**（角色/场景/道具/分镜）出，而跨镜一致性不靠运气、靠结构。

---

## ① 设计哲学：为什么是"三表为上游圣经、分镜向下引用资产"

一个背景很厉害的人，第一件事不是想"怎么让 AI 画得好看"，而是问一个更冷的问题：**漂移从哪里进来的？**

答案是：当同一个空间/同一张脸/同一把刀，在每个镜头里被**重新描述一遍**的时候。每一次重述都是一次重新掷骰子。十个镜头描述十遍红木圆桌，就会得到十张不同的红木圆桌。所以真正的资深做法是把电影工业里"**制片圣经（Production Bible）**"那套搬过来——**先把世界钉死，再拍镜头**。

由此推出三条第一性原理，贯穿整个 skill：

1. **一处定义·处处引用（Single Source of Truth）**。每个叙事实体（角色/场景/道具）只在它的专属表里被定义一次，分配一个 `asset_id`；分镜表里**禁止重述外观**，只能用 `[Element_*]` 引用。重述即漂移入口，从语法层面堵死。
2. **参数优先于形容词（Parameters over Adjectives）**。"高级灰"不可复现，"#6B6B6B / 色温 5500K / 光比 4:1"可复现。可量化维度一律落成数值+单位。这把"导演的审美直觉"翻译成"下游引擎能咬死的约束"。
3. **三表是上游空间/身份/物质锚，分镜是下游时间轴**。角色表锚定"谁"、场景表锚定"哪里"、道具表锚定"什么东西+它怎么演变"，分镜表只负责"在第几秒、用哪个机位、调度上面这些已锚定的事实"。**上游静态、下游动态**——这是整个依赖图能成立的根。

至于"默会知识"——它的高明之处恰恰在于**它不出现在产物里**。默会引擎做三件用户看不见的事：

- **自动分焦点/从属**：扫全本时，资深制片一眼能分出"林辰=主焦点角色（全片锚定、多 Look 归并）"vs"路人甲=从属（轻锚定）"。skill 把这套分级内建进抽取步骤，而不是要用户标注。
- **识别叙事道具 vs 布景道具**：满桌杯盘里，只有"那把有 3 处缺口的刀""那份'云途'文件"是**会推动剧情、会状态演变**的叙事道具，需要进道具表并上状态轴；其余是布景，归场景表。这一刀切得准不准，是外行和内行的分水岭。
- **引擎隐身 + 自检不外显**：所有"为什么这么定"的推理、§8 自检清单、纠错过程，只在内部跑，**绝不写进成片表格**。产物干净得像一份交付文档，而不是一段思考过程。

## ② 依赖 DAG 与"一次生成"的数据流

```
                         ┌─────────────────────────┐
              剧本全文 →  │  ① 寓居通读（Indwelling） │
                         │  主题 / 情绪曲线 / 氛围母色 │
                         │  / 风格核心               │
                         └────────────┬─────────────┘
                                      │ 母色 + 情绪曲线（贯穿全程的隐性基线）
                                      ▼
                         ┌─────────────────────────┐
                         │  ② 全本实体扫描（默会层）  │
                         │  分焦点/从属 · 去重归并    │
                         │  同角色多Look归并 · 素材绑定│
                         └────────────┬─────────────┘
                                      │ 实体清单（角色集 / 场景集 / 道具集）
                                      ▼
              ┌───────────── ③ 三张上游资产表 · 并行生成 ─────────────┐
              ▼                       ▼                               ▼
      ┌──────────────┐       ┌──────────────┐               ┌──────────────┐
      │   角色表       │       │   场景表       │               │   道具表       │
      │ character-board│       │ color-palette │               │ (本控内联契约) │
      │ §5 锚定结构    │       │ 空间锚/光弧光  │               │ 状态轴 state   │
      │ [Element_Char] │       │ [Element_Loc] │               │ [Element_Prop] │
      └───────┬───────┘       └───────┬───────┘               └───────┬───────┘
              │                       │                               │
              └───────────────┬───────┴───────────────┬───────────────┘
                              │ asset_id 全集（身份+空间+物质）
                              ▼
                  ┌─────────────────────────┐
                  │  ④ 分镜表生成（storyboard │
                  │     v2.0 时长制）         │
                  │  「场景」「连续性锁定」字段 │
                  │   逐项 ID 引用上游资产     │
                  │  + 情绪曲线驱动主光/色温弧 │
                  └────────────┬─────────────┘
                               ▼
                  ┌─────────────────────────┐
                  │  ⑤ 交叉校验（内部·不外显） │
                  │  引用闭合 / 覆盖完整 /     │
                  │  道具状态轴单调 / 跨镜锚一致│
                  └────────────┬─────────────┘
                               ▼
                  ┌─────────────────────────┐
                  │  ⑥ 一次性输出全案四表      │
                  │  （可选：每镜组 Seedance   │
                  │   prompt）                │
                  └─────────────────────────┘
```

**为什么是 DAG 而不是线性管线**：第 ③ 步三表彼此**无依赖**（角色不依赖道具、场景不依赖角色），可并行；第 ④ 步对三表是**汇聚（join）**，必须等三表全出且 asset_id 全集就位才能开始引用。这个结构决定了一致性是"**收口在第 ⑤ 步的一次校验**"，而不是散落在每个镜头里各自保证。

数据流里有一条**贯穿始终的隐性基线**：① 步定下的"情绪曲线 + 氛围母色"不只用一次——它同时是场景表"色彩弧光/主光弧光"的依据（暖金→冷青 6000K→3200K→5500K+），也是分镜表里每镜主光方向/色温的取值依据。**同一条弧光，三处落地，自然对齐**。

## ③ 文件编排：在 director-suite 下如何放

总控作为**编排层（orchestrator）**入驻先前空着的 `production-bible/`，调度既有成员而非重写它们的契约：

```
skills/director-suite/
├── production-bible/              ← 本控（总控/编排层）
│   ├── SKILL.md                   ← 六步流水线 + 内联道具表契约 + 触发词/反触发
│   └── (引用，不复制) ───────────┐
├── character-board/              │
│   └── output-contract.md        │ ← 角色表契约（§5 锚定结构 / asset_id 命名）
├── color-palette/                │ ← 场景表 + 色卡契约（空间锚 / 光弧光）
│   └── output-contract.md        │
├── storyboard/                   │
│   └── output-contract.md (v2.0) │ ← 分镜表契约（时长制 / 连续性锁定 / 引擎隐身）
└── keyframe/                     ┘ ← 关键帧（视觉生成层，下游可选）
```

编排原则三条：

- **契约不重写，只引用**。角色表字段以 `character-board/output-contract.md` 为准，场景表以 `color-palette/output-contract.md` 为准，分镜表以 `storyboard/output-contract.md` v2.0 为准。总控只负责**调度顺序、数据传递、跨表校验**。
- **缺位的成员就地补齐，但保持轻量**。当前 suite 没有独立的道具表成员，总控**内联一份轻量道具表契约**（以"状态轴 state axis"为核心，让道具跨镜单调演变），而非新建一个重型目录——避免过度工程化，等道具表真正需要独立生成时再外迁成正式成员。
- **总控的 frontmatter 负责路由**。`name: director-production-bible`；description 带正向触发词（全案/一次出全套/角色表+场景表+道具表+分镜表/制作圣经/production bible/一站式分镜）+ 一条**反向触发**子句：单表/单产品请求路由回对应单成员，避免总控抢单。

## ④ 一致性如何被结构性保证（而非靠提示词祈祷）

资深的人不信"我提醒模型注意一致性"这种话，他信**结构**。一致性在这套设计里由四层机械装置保证：

| 机制 | 作用 | 失败模式被堵在哪 |
|---|---|---|
| **asset_id 唯一键** `[Element_*]` | 每个实体一个全局唯一引用键，分镜只引不述 | 杜绝"十个镜头十张红木桌" |
| **L1/L2 锚定分级** | L1 主焦点（强锚定、多 Look 归并）；L2 从属（轻锚定） | 把有限的"一致性预算"花在主角和叙事道具上，不被路人稀释 |
| **道具状态轴（state axis）单调演变** | 刀从"完好"→"卷刃"→"染血"，每镜引用某一个**确定状态**而非自由描述 | 杜绝道具状态在镜间反复横跳（上镜染血、下镜又干净） |
| **第 ⑤ 步交叉校验四查** | 引用闭合（分镜引的 id 都在三表里存在）/ 覆盖完整（三表里的实体都被用上或显式弃用）/ 状态轴单调 / 跨镜锚点一致 | 把所有漂移收口在交付前一次拦截，不带病出厂 |

关键洞察：**前三层是"让漂移无法发生"，第四层是"万一发生了在出厂前抓住"**。防御纵深，不是单点祈祷。

而且这四层**全部不外显**——asset_id 是机器可读的引用键，校验是内部跑的清单，用户拿到的是干净的四张表。一致性是"被结构保证的结果"，不是"写在表里的口号"。

## ⑤ 与既有 v2.0 / 四成员如何衔接：文字圣经 vs 视觉生成

这套体系有一条清晰的分工线，错位理解就会重复造轮子：

- **三表 + 分镜表 = 文字圣经（Text Bible）**。它们是**可量化的视觉事实的文字定义**——asset_id、色温、光比、机位、状态轴。它们是"真理之源"，回答"这个世界到底长什么样、怎么演变"。
- **设定板 / 色卡 / 关键帧 = 视觉生成层（Visual Layer）**。`character-board` 出角色设定板图、`color-palette` 出色卡、`keyframe` 出关键帧——它们是**把文字圣经渲染成像素**的下游执行者。

衔接方式：**总控产出文字圣经（四表）→ 视觉层按 asset_id 把每个实体生成一次参考资产 → 资产图与文字定义双向绑定**。已上传的素材直接绑定为对应 asset_id，描述须与素材匹配、不重复生成（"先绑定后生成"）。

与 v2.0 的衔接尤其干净：分镜表本就是 storyboard v2.0 契约，总控不改它一个字段，只是**保证喂给它的「场景/连续性锁定」字段引用的 asset_id 全部来自上游三表**。v2.0 的时长制、引擎隐身、自检不外显——总控全部继承、不破坏。一句话：**总控是调度者，不是改写者**。

## ⑥ 关键取舍与可向用户确认的点

一个厉害的人会把"我替你做了哪些假设"摊开说，而不是闷头干。以下是这套设计里的真实取舍，建议在跑之前与用户对齐：

1. **道具表：内联轻量 vs 独立成员**。当前内联在总控里（状态轴为核心）。取舍理由是避免过度工程化。**可确认**：若项目道具极多、需要独立批量生成道具图，是否外迁为正式成员 `prop-board/`？
2. **焦点分级的粒度**。默认 L1/L2 两级。**可确认**：是否需要 L3（纯布景化人物/一次性道具，连轻锚定都省）？长片可能需要，短片两级足够。
3. **母色与情绪曲线的话语权**。默认由 ① 步寓居通读自动推定（如《翡翠楼夜宴》暖金→冷青）。**可确认**：用户是否已有既定的视觉基调/参考片，要直接注入而非自动推定？
4. **"一次全出" vs "分阶段确认"**。默认一次性输出四表。**可确认**：是否希望在第 ③ 步三表出完后**暂停让用户审一遍**再生成分镜？长片强烈建议分阶段，短片可一次到底。
5. **输出是否附 Seedance prompt**。默认四表为主、prompt 可选。**可确认**：是否每镜组都要附引擎 prompt，还是只交付文字圣经由用户自行接引擎？
6. **覆盖完整的严格度**。第 ⑤ 步默认"三表实体必须被用上或显式弃用"。**可确认**：是否允许"备用资产"（定义了但本片不用、留给续集）豁免该检查？

## ⑦ 微型 Worked Example：《翡翠楼夜宴》

**输入（剧本片段語义）**：林辰与王凯在初创办公室谈崩 → 同赴翡翠楼 → S3 包厢红木圆桌前，赵山河与三位前辈摊牌"云途"项目，烟灰缸渐满、刀光乍现。

**① 寓居通读** → 主题：理想主义在资本前的祛魅；情绪曲线：暖（初心）→ 冷（背叛）；氛围母色：暖金衰减为冷青；风格核心：商战黑色电影（noir）。

**② 实体抽取（默会分级 + 归并）**：

| 实体 | 类型 | 焦点级 | 处理 |
|---|---|---|---|
| 林辰 | 角色 | L1 | 强锚定，全片多 Look 归并（西装/卷袖两 Look） |
| 王凯、赵山河 | 角色 | L1 | 强锚定 |
| 三位前辈 | 角色 | L2 | 轻锚定（群像） |
| 初创办公室 / 翡翠楼外 / S3 包厢 | 场景 | — | 各分配空间锚 |
| 有缺口的刀 / "云途"文件 / 烟灰缸 | 道具 | 叙事 | 进道具表，上状态轴 |
| 满桌杯盘 | 道具 | 布景 | 归场景表，不进道具表 |

**③ 三表片段（节选）**：

```
# 角色表
- asset_id: [Element_LinChen_Suit]   L1  | 男/32/瘦削/三七分；深灰西装；眼神：理想未灭
  反向锚定：非油头、非啤酒肚、不佩戴任何徽章

# 场景表
- asset_id: [Element_Box_Jadehall]   S3包厢
  空间锚：红木圆桌 Ø160cm 居中；主光弧光段=冷青 5500K+；光比 4:1；焦点 Focus(0.5,0.55)
  （注：满桌杯盘作为布景在此锚定，不单列道具）

# 道具表
- asset_id: [Element_Knife_Notched]  叙事道具
  状态轴：S0 完好刃 → S1 三处缺口/刀身氧化发黑 → S2 刃口染血
  尺寸：刃长 24cm；木柄裂纹 2 道
```

**④ 一条分镜引用 asset（storyboard v2.0，节选一镜组）**：

```
镜组 12 | 时长 3.5s | 景别 CU 特写 | 机位 桌面平视微仰
画面：赵山河指节叩击桌面，刀被推出半寸
场景：[Element_Box_Jadehall]
连续性锁定：[Element_ZhaoShanhe] + [Element_Knife_Notched]@S1 + 主光 5500K 冷青/光比4:1
（注意：此处刀引用 @S1 缺口态——因第10镜组已发生卷刃，状态轴单调不可回退）
```

注意最后一行的力量：分镜**没有重新描述这把刀长什么样**，只写了 `[Element_Knife_Notched]@S1`。刀的全部物理事实在道具表里钉死，这里只声明"用它的 S1 状态"。这就是整套设计的缩影——**跨镜不漂，因为根本没给重述的机会**。

**一句话收束**：一个真正厉害的人，会把这个 skill 设计成一台"**先建世界、再拍镜头、出厂前过安检**"的机器——三表是世界的宪法，分镜是宪法的执行，asset_id 是引用宪法的法条号，而所有默会的盘算与自检都藏在幕后，让交付物干净得像一位资深制片亲手写的制作圣经。
