## 1. 问题陈述 Problem

**现状（引 director-suite 具体文件）：**

director-suite 已经在多个文件里**零散地写了省钱纪律**，但**从来没有把它们提炼成一个可查、可量化、可校验的"成本规划层"**。逐文件核对，省钱知识散落如下：

- **生成单元打满省次数**：`storyboard/output-contract.md` §1 表把"镜头组 = 一个视频模型生成单元（Seedance 单次 4–15s）"定为 **约 10–15s**；§5「双时长观」与 `_shared/seedance-2.0.md` §0/§5 反复强调"**禁止**把组内每个 2–3s 的镜各自送一次生成（碎、贵、不连贯、且低于 4s 下限）"。这是**全套件唯一明写"贵"字的省钱纪律**，但它只活在"双时长观"语境里，没有被抽象成"每次生成都有成本、要把生成窗口吃满"的通则。
- **同工具降级**：`_shared/continuity-quality.md` 二·7「失败处理协议」写"**同工具内降级优先**"`Seedance 2.0 → Seedance 2.0 Fast`、`ImagesToVideo` 内换 Vidu Q3、兜底链 `GPT Image 2 → Nano Banana Pro`。但这是**失败后的兜底**语境（"失败先在同一生成工具内重试或降级"），**不是"主动为省成本而降级"**——同一条降级链既是"救火"也是"省钱"，套件只写了救火面。
- **720p 生成 → 超分链**：`_shared/continuity-quality.md` 二·2「分辨率基准」写"视频生成 **720p 生成 → MediaKit 超分至 1080p/2K/4K**""**不要对成片整体超分/插帧**"；`pro-params.md` 四给了帧率/画幅的规格表。这是一条**典型的"先省着生成、后期再拉规格"的成本策略**，但它被埋在"质量标准/分辨率基准"小节，读者只当它是"画质规格"，没意识到它本质是**成本杠杆**（720p 生成比 1080p 直生省，超分是后期廉价补规格）。
- **视频参考门槛（默认不加）**：`_shared/continuity-quality.md` 一·4「视频参考的门槛原则」明写"**不要为了'连贯'就给每镜都加视频参考。视频参考会拖慢、耗积分**""**默认不加** `reference_video`；仅当本镜与前镜**极强连续**才追加""**递进收紧**：板/镜数越多，启用门槛越高"。这是**最接近"成本意识"的一条纪律**，但它的论证落点是"连贯性正收益"，"耗积分"只是顺带一提，没有把"加一条 reference_video = 多花多少代价"明确成可决策的成本项。
- **首尾帧承接的成本档位**：`continuity-quality.md` 一·3 与 `keyframe/output-contract.md` 已隐含"**方案一·末帧续首帧 = 快、省积分**""**方案二·视频续接 = 慢、极耗积分**"的成本-质量权衡表（`continuity-quality.md` 一·3 表的"代价"列直接写了"省积分 / 极耗积分"）。这张表**已经是成本表的雏形**，但它被定位成"连续性技术选型"，没有被纳入一个统一的成本决策框架。

**痛点（为何是问题）：**

1. **省钱纪律是"散文劝告"，不是"可执行规划"（缺口类 A 的典型形态）。** 上述 5 条纪律全部以自然语言散落在 `continuity-quality.md` / `storyboard` / `seedance-2.0` / `pro-params` 四个文件的不同小节，**没有任何成员在产出分镜/全案时主动把它们汇总成一份"成本规划"**。导演的"质量判断"被结构化到了焦段/色温/dBFS，但"成本判断"完全没有结构化——一个镜头组该不该加 reference_video、该不该用 Fast 档、几张关键帧能省、这一稿大概要花多少次生成，**全靠操作员凭记忆翻四个文件的散落条款**，规模化即崩、且极易漏项（最常见漏项：默认给每镜都加 reference_video，直接把积分翻几倍）。
2. **"成本"在套件里没有任何度量单位，无法决策、无法对账。** 套件通篇没有一个"生成次数 / 积分 / 代价档位"的可量化字段。`continuity-quality.md` 一·3 写了"省积分/极耗积分"是**定性形容词**，不是"方案一 ≈1× 生成、方案二 ≈Nx 生成"的可比数值。结果是：用户在点付费按钮（CLAUDE.md「导演台『生成站位』会真调 gemini-3.1，由用户亲自点」）**之前看不到一个"这稿预计 X 次生成"的预算估算**，点下去才知道贵，事后也无法对账"实际花了多少 vs 规划多少"。
3. **成本-质量是单向决策（缺口类 B 的影子）。** 当前套件对"质量"是前向最大化的（8K、毛孔级、首尾帧最流畅方案……），对"成本"只有失败后的被动降级（同工具救火），**没有"在质量可接受下界内主动选最省方案"的双向决策**。用户想要"这条片我预算只够 30 次生成，帮我在质量够用的前提下省着拍"——套件无任何字段/机制承接这个诉求。
4. **省钱口径四处不一致、互相不引用。** `seedance-2.0.md` 的"打满窗口省次数"、`continuity-quality.md` 的"降级/超分/参考门槛"、`keyframe` 的"末帧续首帧省积分"——**四处各说各的，没有单一事实源（SoT），也没有一处把它们交叉引用**。换一条省钱策略要在四个文件里找、且可能漏。这正是"成本知识无 SoT"的 B 类症状。

> 一句话：**套件有零散的省钱肌肉记忆，但没有"成本意识"这块脑子**——没有度量、没有预算、没有主动省钱的决策层，省不省全凭操作员手感。这是缺口类 A（有脑无手·省钱手感没被结构化）叠加 B（成本知识无 SoT·单向只会救火不会主动省）。

## 3. 目标与非目标 Goals / Non-Goals

**Goals：**

- **G1**：新建 `_shared/cost.md` 作为**成本规划单一事实源**，把散落在 `continuity-quality.md` / `storyboard` / `seedance-2.0` / `pro-params` 的 5 条省钱纪律收口成一张**成本决策表**（生成单元打满 / 同工具降级 / 720p→超分链 / 视频参考门槛 / 首尾帧成本档位），并给每条标"省什么、省多少（相对代价）、质量代价、何时用/不用"。
- **G2**：给生成动作引入一个**相对成本度量** `gen_cost`（以"一次基准视频生成 = 1.0×"为单位的相对代价系数，**非真实货币/积分**），让"加一条 reference_video""用首尾帧方案二""11 张关键帧各自 TextToImage"等动作有可比代价数值，从而可决策、可估算、可对账。
- **G3**：让 storyboard / production-bible 的管线在出稿时**主动产出一份"成本规划摘要"**（对内过程产物）：预计生成次数 / 相对代价总分 / 触发了哪些省钱策略 / 哪些镜头组为省成本做了降级——供用户在**点付费按钮前**看到预算估算。
- **G4**：定义**成本-质量双向决策**：在用户给定"质量下界 + 预算上限"时，按成本决策表在"质量可接受区间内选最省方案"（如：非强连续镜默认不加 reference_video、铺陈组用 Fast 档、关键帧能末帧续首帧就不视频续接）；用户未给预算时默认"质量优先、省钱策略只取无质量损失的几条"（打满窗口 / 默认不加视频参考 / ImageToImage 复用）。
- **G5**：复用而非新造——降级链/模型分级复用 D3，质量下界口径复用 `continuity-quality.md` 二（质量标准），暂停门复用 D1 的 `pause_gate`；D11 只新增"成本度量 + 成本决策表 + 预算估算/对账"这层薄壳。

**Non-Goals（明确边界）：**

- **NG1（不破引擎隐身 · 铁律）**：成本规划摘要、`gen_cost` 系数、预算估算、降级决策理由、"为省钱选了 Fast 档"——**全部是过程产物，绝不可漏进任何成片提示词**。引擎隐身（`storyboard/output-contract.md` §7.8「自检/审计/过程产物绝不写进最终镜头卡」、`production-bible/SKILL.md` 铁律③）在此扩展为"**成本规划层绝不漏进成图/成片**"。镜头卡与 Seedance/图像 prompt 里**不出现** `gen_cost`/`1.0×`/`预算`/`省积分`/`降级到 Fast`/`成本` 等任何成本词。
- **NG2（不破可移植性）**：`cost.md` = 纯 Markdown 知识层，`gen_cost` 是**相对系数（无量纲、宿主无关）**，**绝不写死任何真实货币价格 / 具体积分单价 / 某宿主计费规则**（那些随宿主/时间漂移，写死即过时）。真实计费换算（系数 → 实际积分/钱）是宿主/ViMax ledger 的事（见 MEMORY「ViMax 解耦接入 α′」的 ledger 计费），D11 只产"相对代价 + 触发的省钱策略"，宿主无计费能力时优雅降级为"只给生成次数估算、不给货币"。
- **NG3（不替宿主做计费 / 不点付费按钮）**：D11 只产**规划与估算**，**不实现真实扣费、不调用生成 API、不点付费按钮**（沿用 CLAUDE.md「付费按钮用户亲点」铁律）。真机出片 + 真实账单对账由用户亲点、宿主 ledger 记。
- **NG4（不牺牲质量下界省钱）**：省钱**绝不可击穿质量下界**——不得为省钱违反 `continuity-quality.md` 二（单 shot ≤15s 安全值、写实物理铁律、音画同步 ≤1 帧）、不得为省钱跳过强连续镜该有的 reference_video（强连续是质量刚需，不是可省项）、不得为省钱用 Fast 档拍高潮/换脸/数字人这类一致性刚需镜。省钱只在"质量冗余区"动手。
- **NG5（不另造降级链 / 不重写 Bone）**：降级链复用 D3 `model-registry` fallback；模型快省档（NB2）复用 D3 image `_routing`；首尾帧成本档复用 `continuity-quality.md` 一·3 既有表；视频参考门槛复用 `continuity-quality.md` 一·4。D11 **只新增成本度量与决策框架**，把既有散落条款交叉引用进来，不整段复制（megaprompt 导出版除外）。

## 4. 需求 Requirements

### 4.1 功能需求 FR

**D11-FR-01 · 成本规划单一事实源 `_shared/cost.md`（收口 5 条省钱纪律 + 度量单位）**
- 描述：新建 `_shared/cost.md`，作为成本知识 SoT。开篇定义**相对成本度量** `gen_cost`：以"**一次基准视频生成（一个 10–15s 镜头组、720p、Seedance 标准档、无视频参考）= 1.0×**"为基准单位，其余动作给相对系数（见 §5.3 表）。然后用一张**成本决策表**收口 5 条省钱纪律，每条含五列：`策略名 / 省什么 / 相对代价变化 / 质量代价 / 触发条件(何时用·何时禁用)`。5 条策略：① 生成单元打满（组内镜不各自生成）；② 同工具降级（Seedance→Fast，复用 D3）；③ 720p 生成→超分（不直生高分、不整片超分）；④ 视频参考门槛（默认不加，复用 `continuity-quality.md` 一·4）；⑤ 首尾帧成本档（末帧续首帧 vs 视频续接，复用 `continuity-quality.md` 一·3）。表内所有阈值/链条均以**交叉引用**指向既有文件，不另立新值。
- 可量化验收：①`_shared/cost.md` 存在且含 `gen_cost` 基准定义（1.0× = 一次标准镜头组生成）；②成本决策表恰含上述 5 条策略，每条五列齐全（缺列即不合格，schema 校验）；③5 条策略各自显式 `→ 见 <文件>:<小节>` 交叉引用到源条款（生成单元打满→`storyboard/output-contract.md` §1/§5 + `seedance-2.0.md` §0；降级→D3 `model-registry`/`continuity-quality.md` 二·7；超分→`continuity-quality.md` 二·2；视频参考→`continuity-quality.md` 一·4；首尾帧→`continuity-quality.md` 一·3）；④对成图/成片提示词 grep 成本词（`gen_cost`/`1.0×`/`相对代价`/`预算`/`省积分`），命中 = 0（NG1 闸）。

**D11-FR-02 · 生成单元打满规划（把 10–15s 窗口吃满 · 省次数主策略）**
- 描述：把 `storyboard/output-contract.md` §1/§5 的"镜头组=生成单元 10–15s、组内镜不各自生成"从"双时长观纪律"提升为**成本主策略**，并给可量化判据：(a) **窗口利用率** `fill_ratio = 镜头组时长 / 15s`，铺陈/常规组应 ≥0.67（即 ≥10s，吃满推荐窗口下沿），低于 0.67 须有叙事理由（如极短转场组）；(b) **碎切惩罚**：若把组内某 2–3s 镜单独拎出生成，记为违规（违反 `seedance-2.0.md` §0「禁止把组内每个 2–3s 镜各自送一次生成」），成本规划摘要须标红；(c) **ImageToImage 复用省重画**：同角色/商品的后续帧默认以"先生成的首图"为参考（ImageToImage，沿用 `continuity-quality.md` 一·1），不各自 TextToImage 重画，复用记 `gen_cost` 折扣（见 §5.3）。
- 可量化验收：①每个镜头组在成本规划摘要里携带 `fill_ratio` 值；②`fill_ratio < 0.67` 的组必须在摘要标注叙事理由，无理由即标红（不合格）；③成本规划摘要统计"碎切违规数"，正常稿应 = 0；④多帧同主体场景默认走 ImageToImage 链（摘要标"复用基准图 @asset_id"），各自 TextToImage 的数量被统计为"重画次数"。

**D11-FR-03 · 成本-质量降级决策表（主动省 · 复用 D3 链 · 守质量下界）**
- 描述：定义一张**主动降级决策表**（区别于 D3/continuity 的"失败救火降级"）：在"质量下界内"按镜头属性决定是否降档省成本。决策维度：`镜头属性(铺陈/叙事/高潮/换脸数字人) × 一致性刚需度 × 预算紧张度` → `推荐档位(标准/Fast) + 是否加视频参考 + 首尾帧方案`。**硬约束（NG4 落地）**：高潮镜 / 换脸 / 数字人 / POV / 强连续镜**禁止为省钱降到 Fast 档、禁止省掉刚需 reference_video**（这些是质量刚需，不在可省区）；铺陈组 / 空镜 / 中性交代镜在预算紧张时**可降 Fast 档、可走末帧续首帧而非视频续接**。降级链本身复用 D3 `model-registry` fallback（`seedance-2.0 → seedance-2.0-fast`、image NB2 快省档）。
- 可量化验收：①决策表覆盖 ≥4 类镜头属性（铺陈/叙事/高潮/换脸数字人），每行给"推荐档位 + 视频参考 + 首尾帧方案 + 是否可省(对内理由)"；②表内**硬约束行**明确标"高潮/换脸/数字人/POV/强连续 = 禁降档"（NG4 闸，缺失即不合格）；③降级目标全部指向 D3 `model-registry`/`continuity-quality.md` 二·7 既有链，无新造链（grep 验证降级目标 ∈ 既有链集合）；④对成片提示词 grep "降级/Fast/省钱" 命中 = 0（降级是对内决策，不进成片，NG1 闸）。

**D11-FR-04 · 预算估算 + 真机后对账（出稿前给数、出片后核账）**
- 描述：在 storyboard / production-bible 管线**新增一步"成本规划"**（出稿后、真机前）：(a) **预算估算**——按全稿镜头组数 × 各组 `gen_cost`（含视频参考/首尾帧/降档调整）+ 关键帧/图像生成次数，汇总出"**预计生成次数 N ± 容差** + **相对代价总分 Σgen_cost**"，作为**对内过程产物**呈现给用户（让用户点付费前知道预算量级）；(b) **预算门**（复用 D1 `pause_gate`）——当 Σgen_cost 超过用户给定上限时，在暂停门提示"超预算，建议降级 X 组"并给出降级后估算，**由用户决定是否放行**（不自动降、不自动付费，NG3）；(c) **真机后对账**——真机出片后（用户亲点付费、宿主 ledger 记实际数），把"规划 Σgen_cost / 预计次数 N" 与"宿主 ledger 实际生成次数"对账，输出差异（用于校准 `gen_cost` 系数，对内）。
- 可量化验收：①管线产出"成本规划摘要"含三项：预计生成次数 N（含容差）、相对代价总分 Σgen_cost、触发的省钱策略清单；②当给定预算上限且 Σgen_cost 超限时，规划摘要明确标"超预算 + 建议降级组 + 降级后估算"（不自动执行降级/付费）；③对账段：规划次数 N vs ledger 实际次数，给出差异值与方向（高估/低估）；④成本规划摘要全程**标注为对内过程产物**，grep 成片提示词中成本摘要字段命中 = 0（NG1 闸）。

**D11-FR-05 · 成本-质量双向决策默认策略（省钱不破质量下界）**
- 描述：定义两套默认档：(a) **质量优先档（默认 · 用户未给预算）**——只启用"**零质量损失**"的省钱策略：生成单元打满（FR-02）、视频参考默认不加（`continuity-quality.md` 一·4，本就是质量+成本双赢）、ImageToImage 复用（避免重画漂移，质量+成本双赢）；**不**主动降 Fast、**不**牺牲首尾帧流畅度。(b) **预算优先档（用户给预算上限且 Σ超限）**——在 (a) 基础上叠加"**有质量代价但在下界内**"的省钱策略：铺陈/空镜组降 Fast 档、非强连续镜走末帧续首帧（而非视频续接）、关键帧合并（能用一张兼用首尾就不出两张）。**两档都受 NG4 硬约束**：高潮/换脸/数字人/POV/强连续镜任何档都不降质量。
- 可量化验收：①两套默认档在 `cost.md` 明确成文（质量优先档启用策略清单 / 预算优先档追加策略清单）；②质量优先档的策略全部标"零质量损失"且可逐条验证（打满/默认不加参考/ImageToImage 均不损质量）；③预算优先档每条追加策略标"质量代价 + 仅作用于非刚需镜"；④两档均显式声明"NG4 硬约束镜（高潮/换脸/数字人/POV/强连续）豁免降级"。

**D11-FR-06 · 成员落地（cost.md + 管线注册 + 路由 + 交叉引用 + README）**
- 描述：按套件既有结构落地：(a) 新建 `_shared/cost.md`（FR-01~05 全部表 + 两套默认档 + 自检门）；(b) 在 `storyboard/SKILL.md` 与 `production-bible/SKILL.md` 的管线**路由表新增一行**"出稿后→读 `_shared/cost.md` 做成本规划 + 预算估算"（正文增量 ≤5 行，渐进式披露，不默认全量内联）；(c) 在 `continuity-quality.md` 一·3/一·4/二·2/二·7、`storyboard/output-contract.md` §5、`seedance-2.0.md` §0 的源条款处**加交叉引用注脚**"→ 成本规划统一口径见 `_shared/cost.md`"（只加引用、不改既有语义）；(d) `README.md` 三层架构表的"骨②"行 + 目录结构树新增 `cost.md` 节点；(e) `_megaprompts/` 相关导出版内联 `cost.md` 核心表（自包含）。
- 可量化验收：①`_shared/cost.md` 存在；②`storyboard/SKILL.md`/`production-bible/SKILL.md` 路由表各新增"成本规划"一行，正文增量 ≤5 行（diff 验证）；③上述 6 处源条款均加了指向 `cost.md` 的交叉引用注脚（grep 验证）；④`README.md` 骨②行与目录树含 `cost.md`；⑤megaprompt 导出版内联 cost 核心表，可独立运行。

### 4.2 非功能需求 NFR

**D11-NFR-01 · 引擎隐身 + 成本层不漏进成片（铁律 · 一票否决）**
`gen_cost` 系数、预算估算、Σgen_cost 总分、成本规划摘要、降级决策理由、"为省钱选 Fast/省 reference_video"、对账差异——**全属过程产物，绝不出现在任何成片提示词 / 镜头卡里**。引擎术语（Polanyi/默会/支柱编号/方法论/格式塔/寓居）仍零出现。验收：对全稿所有成片提示词与镜头卡 grep `gen_cost|1\.0×|相对代价|预算|Σgen|省积分|省钱|降级到 Fast|成本|cost_summary|Polanyi|默会|支柱|方法论`，命中 = 0。

**D11-NFR-02 · 可移植性 / 宿主无关（相对系数，不写死货币）**
`cost.md` = 纯 Markdown，零运行时依赖。`gen_cost` 是**无量纲相对系数**，**绝不写死真实货币价 / 积分单价 / 某宿主计费规则**。真实计费换算由宿主/ViMax ledger 负责；宿主无 ledger 时优雅降级为"只给生成次数估算 N，不给货币"。验收：`cost.md` 内 grep 真实货币符号 / 具体积分单价（`¥`/`$`/`元/次`/`X 积分`）命中 = 0；只出现相对系数（`1.0×`/`0.6×` 等）与生成次数（`N 次`）。

**D11-NFR-03 · 不破质量下界（省钱有底线）**
任何省钱策略不得违反 `continuity-quality.md` 二（质量标准：单 shot ≤15s、写实物理铁律、音画同步 ≤1 帧、画幅无黑边无拉伸）与一致性刚需（强连续镜的 reference_video、换脸的身份双保险）。FR-03/FR-05 的 NG4 硬约束镜（高潮/换脸/数字人/POV/强连续）在任何预算档都豁免降级。验收：降级决策表含明确"禁降档镜"清单；构造"对高潮镜降 Fast"的反例，自检脚本须报不合格。

**D11-NFR-04 · 复用而非新造（DRY · 不重写降级链/质量标准）**
降级链复用 D3 `model-registry` fallback；模型快省档复用 D3 image `_routing` NB2；首尾帧成本档复用 `continuity-quality.md` 一·3；视频参考门槛复用 `continuity-quality.md` 一·4；质量下界复用 `continuity-quality.md` 二；暂停门复用 D1 `pause_gate`。D11 **只新增成本度量 + 决策框架 + 预算估算/对账**。验收：`cost.md` 中降级目标 / 首尾帧方案 / 视频参考门槛 / 质量阈值均以交叉引用形式指向既有文件，未整段复制（megaprompt 导出版除外）。

**D11-NFR-05 · 估算诚实性（给区间不假装精确）**
`gen_cost` 与预计次数 N 是**规划估算**，非保证值（真机受重摇/失败重试/分辨率/模型影响）。估算必须给**区间或 ± 容差**（如"预计 28–34 次"），**不假装精确到次**（沿用 `storyboard/output-contract.md` §1「长对白时长按估值标 `≈`，不假装精确到帧」的诚实口径）。真机后对账校准系数，但不追求零误差。验收：成本规划摘要的预计次数以区间 / `±容差` 形式给出，无"精确 N 次"的虚假精确；对账段标注"估算 vs 实际"差异为正常现象、用于校准。

### 5.3 关键 schema / 契约字段 / 算法

**(A) `gen_cost` 相对成本度量（FR-01 · 无量纲系数 · 过程产物，绝不入成片）**
```yaml
# 基准：一次「标准镜头组生成」= 1.0×
#   定义 = 一个 10–15s 镜头组 / 720p / 视频标准档 / 无 reference_video
gen_cost_units:                      # 相对系数（宿主无关，NG2：不写死货币/积分单价）
  base_shot_group:        1.0        # 标准镜头组一次生成（基准）
  fast_tier_shot_group:   ~0.5-0.7   # 降 Fast 档（复用 D3 seedance-2.0-fast，省约 30-50%·相对值,真机校准)
  add_reference_video:    +0.3-0.6   # 加一条 reference_video 的增量（拖慢耗积分,continuity 一·4)
  keyframe_text2img:      ~0.3        # 一张关键帧 TextToImage（独立重画）
  keyframe_img2img_reuse: ~0.15       # 以基准图 ImageToImage 复用（约半价,省漂移又省钱）
  endframe_carry:         ~0         # 方案一·末帧续首帧（截帧≈免费,continuity 一·3「省积分」)
  video_carry:            +0.5-1.0   # 方案二·视频续接（极耗积分,continuity 一·3「极耗积分」)
  super_res_upscale:      ~0.1        # 720p→MediaKit 超分（后期廉价补规格,远低于直生高分)
# 注：系数为相对量级、给区间不假装精确（NFR-05），真机后用 ledger 对账校准
```

**(B) 成本决策表（FR-01 · 5 策略五列 · 写入 cost.md · 全交叉引用）**

| 策略 | 省什么 | 相对代价变化 | 质量代价 | 触发条件（何时用 · 何时禁用） |
|---|---|---|---|---|
| ① 生成单元打满 | 省生成次数 | 碎切 N 镜各生成 → 合 1 组：`N×0.x → 1.0×` | **零**（反而更连贯） | 恒用；组时长吃满 10–15s。禁：把 2–3s 镜各自生成（`seedance §0`） |
| ② 同工具降级 Fast | 省单次代价 | `1.0× → ~0.5-0.7×` | 中（细节/动态略降） | 仅铺陈/空镜/中性交代镜；**禁**高潮/换脸/数字人/POV/强连续（NG4）。链见 D3 `model-registry` |
| ③ 720p→超分 | 省直生高分代价 | 直生 1080p+ → `720p(1.0×)+超分(0.1×)` | **零~极低**（不整片超分） | 恒用；视频默认 720p 生成、MediaKit 后期补规格（`continuity 二·2`）。禁：对成片整体超分/插帧 |
| ④ 视频参考门槛 | 省 `reference_video` 增量 | 默认不加 → 省 `+0.3-0.6×/镜` | **零~负**（强连续才有正收益） | 默认不加；仅"极强连续"镜加（`continuity 一·4`）。**禁**：为"连贯"给每镜都加 |
| ⑤ 首尾帧成本档 | 省续接代价 | 末帧续首帧`~0` vs 视频续接`+0.5-1.0×` | 末帧档有"刹车顿挫" | 常规/积分敏感→末帧续首帧；**仅**强连续/一镜到底→视频续接（`continuity 一·3`） |

**(C) 主动降级决策表（FR-03 · 镜头属性 × 预算 → 档位 · NG4 硬约束)**

**(D) 预算估算 + 对账算法（FR-04 · 对内过程产物）**
```
def cost_plan(storyboard, quality_floor, budget_cap=None):
    Σ = 0.0; n_lo = n_hi = 0; triggered = []
    for grp in storyboard.shot_groups:
        c = base_shot_group                              # 1.0× 起步
        grp.fill_ratio = grp.duration / 15               # FR-02 窗口利用率
        if grp.fill_ratio < 0.67 and not grp.has_reason: # 吃不满且无理由
            mark_red(grp, "窗口未打满")
        # 默认档:质量优先(FR-05)——只取零质量损失策略
        if not grp.is_strong_continuity:                 # FR-04 视频参考门槛
            triggered += ["默认不加reference_video"]      # 省 +0.3~0.6×
        else:
            c += add_reference_video                      # 强连续=质量刚需,不省(NG4)
        c += sum(kf_cost(kf) for kf in grp.keyframes)    # 关键帧:img2img复用优先(FR-02)
        # 预算优先档(仅当给了 budget_cap 且总额超限)
        if budget_cap and Σ_so_far_over(budget_cap):
            if grp.is_downgradable():                     # FR-03 禁降档镜豁免
                c = apply_fast_tier(c); triggered += ["铺陈组降Fast"]
        Σ += c
    n_lo, n_hi = estimate_gen_count_range(storyboard, Σ)  # NFR-05 给区间不假装精确
    summary = CostSummary(Σ, (n_lo, n_hi), triggered)     # ← 对内过程产物
    if budget_cap and Σ > budget_cap:                     # FR-04 预算门(复用 D1 pause_gate)
        summary.over_budget = True
        summary.suggest = suggest_downgrades(storyboard, budget_cap)  # 建议,不自动执行(NG3)
    assert_quality_floor(storyboard, quality_floor)       # NFR-03 省钱不破质量下界
    assert leak_scan(storyboard.prompts) == 0             # NFR-01 成本词不漏进成片
    return summary   # 呈现给用户(付费前看预算);真机后 reconcile(summary, ledger) 校准系数

def reconcile(summary, ledger):                           # FR-04 真机后对账
    diff = ledger.actual_gen_count - mid(summary.range)
    return CalibrationNote(diff, direction=sign(diff))    # 对内,用于校准 gen_cost 系数
```

   这是**回归基线门**。
2. **回归 diff（基线）**：以 `_shared/examples/cost-plan-demo.md`（脱敏原创短片成本规划全案）为**固定黄金基线 B0**，冻结其镜头组 fill_ratio / Σgen_cost / 触发策略清单。改 cost.md/管线后重跑脚本，结构断言全绿、leak_scan=0、货币扫描=0 即通过；基线漂移须有理由。

5. **A/B 人评（软指标，佐证质量未塌）**：把"启用省钱策略稿"vs"不省钱稿"对非刚需镜双盲给 ≥3 人评"画质/连贯是否可接受、是否看得出降档"——若评审看不出降档（盲评无显著差异），证明"省钱没破质量下界"（软指标，非阻塞门）。

**测试用例 / 基线：**
- 基线 B0：脱敏原创短片（6 镜头组 + 3 角色 + 8 关键帧，含 1 高潮镜 + 1 换脸/数字人镜 + 4 铺陈/叙事镜），人工标注每组 fill_ratio / 强连续性 / 刚需度作 ground truth。
- 用例 T1：质量优先档（无预算上限）→ 只触发零损失策略（打满/默认不加参考/ImageToImage），Σgen_cost 与基线一致，高潮/换脸镜全标准档。
- 用例 T2：预算优先档（给紧预算上限且 Σ 超限）→ 铺陈组降 Fast/末帧续首帧，高潮/换脸镜**仍标准档不降**（NG4），超预算建议段出现。
- 用例 T3：碎切稿（故意把组内 3 个 2s 镜各自生成）→ 摘要"碎切违规数 ≥1"标红（验 FR-02）。
- 反例 NB1/NB2/NB3：见上，三条铁律闸均须报不合格。

**为何这样能证明"真的有效"：**
- 结构闸（脚本）+ 基线 diff 证明"成本规划产物形态正确、5 策略收口、降级目标复用既有链、过程产物不泄漏"——可量化、可重跑硬断言，非"提升质量/省钱"空话。
- 反例 NB1/NB2/NB3 证明三条铁律闸（成本词漏成片、高潮镜禁降档、货币写死）是**真闸**（能拦截），非摆设。
- 真机账单对账把"省没省钱"落到**客观秤**（ledger 实际生成次数）——启用省钱策略后实际次数**低于**不省钱基线，账单是不会撒谎的最终证据；规划次数 N 命中实际（或可校准）证明估算有效。

**落地可靠性理由（自评 3/5）：**
- 上调因素：①收口的 5 条省钱纪律**已在套件内被 `continuity-quality.md`/`storyboard`/`seedance-2.0`/`pro-params` 写明**，D11 是接地汇总、非空想；②降级链/模型分级复用 D3、暂停门复用 D1，无新架构风险；③`cost.md` 纯 Markdown、相对系数宿主无关、零依赖、可移植；④结构闸/leak_scan/货币扫描/反例是确定性硬断言。
- 扣 2 分因素（**这是简报给"落地可靠性偏低 3/5"的核心原因**）：①**"真省钱"必须真机跑账单才证实**——`gen_cost` 系数是**估算的相对量级**，真实代价受重摇/失败重试/模型档/分辨率/宿主计费规则影响，规划次数与 ledger 实际可能偏差较大，需多次真机校准系数才稳；②真机出片 + ledger 对账**依赖用户亲点付费 + 宿主 ledger 真实记账能力**，e2e 闭环依赖外部协作，无法纯文本自证；③成本-质量"质量下界"的判定（哪些镜"看不出降档"）有主观成分，A/B 盲评样本小、非阻塞。**这三点决定了"省钱有效性"不能靠脚本自证，必须真机跑账单——故不给高分。**
