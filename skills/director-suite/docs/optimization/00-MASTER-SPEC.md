## 0. 执行摘要（TL;DR）

**一句话判断**：director-suite 是一颗优秀的「导演大脑」，但它**有脑无手、单向、单模、无秤**。48 个源影视 skill 不是提示词样例，而是一批**可执行生产流水线**（planner→分析→storyboard→media_generator→video_assembler，带依赖 DAG + 强制暂停门 + 量化审计 + 时间线合成导出）。本规格把"补齐"拆成 **13 个方向 / 4 个缺口类**，并先修"秤"。

| 维度 | 数字 |
|---|---|
| 优化方向 | 13（D1–D13） |
| P0 / P1 / P2·P3 | 2 / 3 / 8 |
| 功能需求 FR 总数 | 70+（见 §4 RTM） |
| 套件侧总工作量 | ≈ **33 人周**（不含宿主 parser/生成链工程） |
| 落地可靠性 5★ | D5、D9（确定性可脚本验证，最稳） |
| 落地可靠性 3★（需先 de-risk） | D2、D11、D12 |
| 两条不可破铁律 | ① 引擎隐身 ② 可移植性（见 §7） |

## 7. 统一验证框架（"可靠可验证"的骨架 · 全方向共用）

> 这是本规格区别于"功能清单"的核心：**每一个 FR 都必须落到下面四层验证之一，并满足两条铁律门**。\
> 标志"很厉害的人"的一点：**每道闸都配反向注入测试，证明它真会变红**。

### 7.1 四层验证（从硬到软）

```
L1 确定性脚本闸  每方向交付 verify_*.py / audit_*.py：结构断言 + 数值阈值 + exit0/1，
   (最硬·可CI)    且【同输入 JSON 逐字节可复现】（无随机/时间戳不入判定区）。
                 例：D5 注色相+30°→判FAIL且测回30°±3°；D9 注红线样本→精确FAIL。
L2 回归 diff     冻结黄金基线（翡翠楼全案/v2全片/各方向 B0），改 _shared/ 后重跑，
   (防劣化)       diff 出 GO / NO-GO。空改动 0 劣化；打乱映射必 NO-GO 且嫌疑指针。
L3 引擎隐身门    leak_scan grep 成片(镜头卡+Seedance提示词) 的"过程/审计/执行/引擎"词表，
   (铁律·一票否决) 命中必须=0；并【反向注入】一行审计/执行元数据，扫描器必须报命中（证非橡皮章）。
L4 真机对图/人评  真机出图/出片，≥3 评审对量化清单核验；A-B 盲评（压满版 vs 基线版）胜≥2/3。
   (终极·软指标)  ★付费按钮一律由用户亲点，agent 不点（grsai/gemini-3.1 计费）。
```

### 7.2 两条不可破铁律门（横切全部 13 方向）

```
铁律① 引擎隐身  审计/执行/过程/成本/解构 等任何中间产物，绝不可漏进"成片"
              （成片 = 镜头卡 + Seedance 提示词 + 四表）。每方向 NFR 必含 leak_scan + 反向注入。
铁律② 可移植性  "手"（生成/合成/工具/账单）属于宿主（幻映/ViMax）；
              skill 文件内 grep 宿主 API(vimax.|render(|.exe) / 真实货币单位 命中必=0。
              加执行/成本层 = 定义机器可消费契约，不是把 ViMax 焊进 skill。
```

### 7.3 程序级 GO/NO-GO（合入门）

```
任何动 _shared/ 或新增成员的 PR，合入前必须：
  ① 该方向 verify_*.py 全 PASS + exit0
  ② run_eval.py（D9）对 5 题基线 0 劣化
  ③ 全成片 leak_scan 命中=0
  ④（涉像素一致性）D5 audit_consistency.py 无新增 FAIL
  四项任一不过 = NO-GO，阻断合入。
```
