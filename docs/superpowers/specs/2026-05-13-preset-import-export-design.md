# 预设提示词导入导出设计

## 背景

外部 Web 预设管理器用于维护系统提示词预设，当前系统预设集中存储在 `config/prompt-presets.json` / 运行时用户目录的预设定义中，并按节点类型拆分，例如 `ai-image`、`ai-text`、`ai-video`、`ai-audio`。

管理方需要在本地配置好一整套提示词后，发给用户导入。提示词属于资产，不能直接把明文提示词文档发给用户，因此需要提供一个“人类打开看不懂、软件可以识别导入”的导出格式。同时，为了内部调试和迁移，导入也必须支持未加密的明文 JSON 预设文件。

## 目标

- 在外部 Web 预设管理器顶部操作区增加 `导入文件` 和 `导出文件` 两个按钮。
- 导出时包含所有节点类型的系统预设，不只导出当前下拉框选中的节点类型。
- 导出文件默认使用加密/混淆格式，用户直接打开不能读懂提示词内容。
- 导入时支持两类文件：
  - 软件导出的加密包，例如 `.hy-presets`。
  - 明文 JSON 预设文件，例如完整的 `prompt-presets.json` 结构。
- 导入成功后使用文件内容全量替换当前所有节点类型的系统预设。
- 导入失败时不写入任何数据，不破坏当前预设。

## 非目标

- 不支持把只有一段提示词正文的普通 `.txt` 自动归类成全节点预设，因为这种文件缺少节点类型、标题、分组、叶子、描述等结构信息。
- 不承诺强 DRM 或绝对防破解。由于软件必须在本地解密并使用提示词，技术上只能做到普通用户直接打开文件不可读。
- 不改变当前“新建系统分组 / 新建系统叶子 / 新建 TXT 预设”的编辑语义。

## 数据范围

导出和导入的数据范围是完整预设定义对象：

```json
{
  "ai-image": [],
  "ai-text": [],
  "ai-video": [],
  "ai-audio": []
}
```

如果后续新增节点类型，只要它已经存在于预设定义对象中，也随同导出和导入。导入校验允许未知节点类型保留，但每个节点类型的值必须是数组。

## 文件格式

加密包建议采用专用后缀 `.hy-presets`，内容包含固定魔数和版本，便于软件识别：

```text
HUANYING_PRESETS_V1:<encoded-payload>
```

`encoded-payload` 内部保存加密后的 JSON 包：

```json
{
  "app": "huanying-preset-pack",
  "version": 1,
  "createdAt": "2026-05-13T00:00:00.000Z",
  "presets": {
    "ai-image": [],
    "ai-text": [],
    "ai-video": [],
    "ai-audio": []
  }
}
```

明文 JSON 导入支持两种结构：

```json
{
  "ai-image": [],
  "ai-text": [],
  "ai-video": [],
  "ai-audio": []
}
```

或：

```json
{
  "app": "huanying-preset-pack",
  "version": 1,
  "presets": {
    "ai-image": [],
    "ai-text": [],
    "ai-video": [],
    "ai-audio": []
  }
}
```

## 加密定位

实现上使用稳定的本地可解密算法即可，目标是让文件内容不是明文 JSON。导出文件需要有固定头部和版本号，导入时先判断头部；匹配加密包则解密，不匹配则尝试按明文 JSON 解析。

密钥可以内置在软件代码中，配合随机盐/随机初始化向量生成每次不同的导出内容。由于密钥在本地软件内，安全定位是“防直接阅读”，不是“防专业逆向”。

## 导出流程

1. 用户点击 `导出文件`。
2. 前端请求当前完整预设定义。
3. 组装导出包元数据和 `presets`。
4. 加密/编码为 `.hy-presets` 内容。
5. 触发浏览器下载，文件名包含日期，例如 `huanying-presets-2026-05-13.hy-presets`。
6. 导出不修改本地预设。

## 导入流程

1. 用户点击 `导入文件`，选择 `.hy-presets` 或 `.json` 文件。
2. 前端读取文件文本。
3. 如果文本以 `HUANYING_PRESETS_V1:` 开头，按加密包解密。
4. 如果不是加密包，按明文 JSON 解析。
5. 标准化为完整 `presets` 对象。
6. 校验结构：
   - 顶层必须是对象。
   - 每个节点类型的值必须是数组。
   - 每个预设项必须至少有 `title`。
   - 叶子预设的 `template` 必须是字符串；系统分组可包含 `subItems`。
7. 校验通过后，调用现有保存接口全量写入。
8. 保存成功后重新读取并刷新管理器列表，同时广播预设变更，让主界面同步。

## 替换策略

导入采用全量替换策略。导入文件里的全节点预设是唯一来源，导入成功后当前系统预设完全以文件内容为准。

如果导入文件只包含部分节点类型，缺失的节点类型按空数组处理，避免旧数据残留造成管理方无法控制最终状态。

## 错误处理

导入失败时保持当前预设不变，并给出明确提示：

- 文件格式无法识别。
- 加密包损坏或解密失败。
- JSON 格式错误。
- 预设结构不合法。
- 保存失败。

导出失败时只提示失败原因，不修改任何数据。

## 测试要求

- 加密包导出后不能直接解析为明文 JSON。
- 加密包导入后能还原完整全节点预设。
- 明文 `prompt-presets.json` 能导入并全量替换。
- 明文包装格式 `{ app, version, presets }` 能导入。
- 损坏加密包导入失败且不会写入。
- 结构非法的 JSON 导入失败且不会写入。
- 导入部分节点类型时，未出现的节点类型被替换为空数组。
- 导入成功后当前页面列表刷新，当前节点类型选择保持可用。
