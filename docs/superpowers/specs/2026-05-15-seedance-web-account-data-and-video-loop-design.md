# 海外版 Seedance 账号数据与视频生成闭环设计

日期：2026-05-15

## 背景

海外版 Dreamina/Seedance 不能继续沿用国内版 `dreamina.exe` CLI，因此当前方案是用独立的 `seedance_web` 扩展桥接入海外网页。前一版设计已经明确了可拔插边界：国内版 CLI 不动，海外版走 `integrations/seedance_extension_bridge/`。

当前问题是：工作台曾经把“网页打开、能看到输入框或生成按钮”误判为“已登录”。这不满足真实使用目标。用户最终目标不是 UI 显示已登录，而是工作台能真实使用海外版生成视频，并把视频结果带回工作台。

本设计修正核心标准：**海外版登录成功必须以网页账号数据能成功返回为准；视频生成成功必须以工作台拿回视频文件为准。**

## 目标

1. 保持国内版即梦 CLI 链路不变。
2. 海外版继续使用现有 Chromium + 扩展桥架构，不推翻整体设计。
3. 将“登录成功”的判定改为账号数据成功返回，而不是页面控件猜测。
4. 工作台可提交海外版视频任务，扩展自动操作网页生成视频，并把视频文件回传到工作台。
5. 失败时返回真实原因到工作台节点错误信息，不使用短暂 toast 掩盖问题。

## 非目标

1. 本次不做二维码登录。
2. 本次不把海外版塞进 `DreaminaCliService`。
3. 本次不重构国内版即梦、普通图片、文字、音频等其他节点链路。
4. 本次不打包 EXE，除非用户单独要求。
5. 本次不承诺绕过海外版网站验证码、风控、余额不足或平台限制。

## 成功标准

### 账号连接成功

海外版显示“已登录”必须同时满足：

1. 扩展能连接到海外 Dreamina/CapCut 页面。
2. 页面没有明确的 `Sign in` / `Login` 未登录入口。
3. 扩展或后台能成功拿到账号数据。

账号数据可以是以下任一类强证据：

- 余额或额度文本。
- 账号菜单中的用户标识。
- 海外网页内部接口返回的用户信息。
- 海外网页内部接口返回的余额、权益或订阅信息。

只看到提示词输入框、上传入口、生成按钮，不再算登录成功。

### 视频生成成功

完整闭环必须满足：

1. 工作台创建海外版视频任务。
2. 扩展领取任务。
3. 扩展进入海外版生成页。
4. 扩展填入提示词、上传参考图、设置参数。
5. 扩展点击生成。
6. 扩展等待生成结果。
7. 扩展下载或抓取视频文件。
8. 扩展上传视频到工作台。
9. 工作台节点拿到本地视频路径并完成。

## 状态设计
、
海外版状态分为四层：

```text
not_connected        扩展或浏览器未连接
page_connected       网页已连接，但账号未确认
account_connected    账号数据已返回，登录成功
task_ready           账号已确认，且生成页面可执行任务
```

UI 可继续显示“已登录”，但只有 `account_connected` 或 `task_ready` 才能显示。

如果用户点击“退出登录”，工作台必须立即清空本地海外版状态，并且后续只有重新拿到账号数据后才能再次显示已登录。

## 后端接口调整

保留现有接口前缀：

```text
/api/v2/seedance-web/status
/api/v2/seedance-web/login
/api/v2/seedance-web/logout
/api/v2/seedance-web/page-status
```

补齐任务闭环接口：

```text
POST /api/v2/seedance-web/tasks
GET  /api/v2/seedance-web/query_result
POST /api/v2/seedance-web/bridge/api/tasks/ack
GET  /api/v2/seedance-web/bridge/api/tasks/pending
POST /api/v2/seedance-web/bridge/api/tasks/status
POST /api/v2/seedance-web/bridge/api/files/upload
```

`/status` 返回值需要包含：

```json
{
  "provider": "seedance_web",
  "loggedIn": true,
  "connectionState": "account_connected",
  "account": {
    "displayName": "",
    "userId": "",
    "balanceText": ""
  },
  "pageStatus": {}
}
```

`loggedIn` 只由账号数据强证据决定。

## 扩展侧账号数据获取

扩展需要优先做两类探测：

1. DOM 探测：查找余额、账号菜单、头像菜单、用户标识、登录按钮。
2. 页面接口探测：观察或主动读取海外网页已有的用户/余额接口返回。

判定规则：

- 看到 `Sign in` 或 `Login`：强制未登录。
- 成功拿到余额或账号数据：登录成功。
- 只看到编辑器或生成按钮：页面已连接，但账号未确认。
- 账号数据曾经成功返回，但后来出现 `Sign in`：立即变为未登录。

## 视频任务数据流

```text
工作台视频节点
  -> POST /api/v2/seedance-web/tasks
  -> 后端保存任务 pending
  -> 扩展 pending 接口领取任务
  -> 扩展操作海外网页
  -> 扩展回报 processing / failed / completed
  -> 扩展上传视频文件
  -> 工作台 query_result 获取本地视频路径
```

后端任务状态：

```text
pending
acked
processing
submitted
completed
failed
timeout
```

失败状态必须保留 `error` 字段，前端节点展示这个错误。

## 错误处理

必须明确返回以下错误：

- 海外版网页未连接。
- 海外版账号未登录，页面出现 Sign in。
- 无法读取账号数据，登录态未确认。
- 找不到提示词输入框。
- 找不到上传入口。
- 找不到生成按钮。
- 上传参考图失败。
- 点击生成失败。
- 网页提示余额不足或权益不足。
- 生成超时。
- 找不到生成结果视频。
- 视频上传回工作台失败。

## 测试范围

1. 单元测试：`Sign in` 出现时强制未登录。
2. 单元测试：只有输入框/生成按钮不能显示已登录。
3. 单元测试：返回余额或账号数据后才显示已登录。
4. 单元测试：点击退出登录后清空账号状态，不被旧页面心跳恢复。
5. 单元测试：任务从 pending 到 completed 能返回视频路径。
6. 单元测试：任务失败时错误信息能保存并返回。
7. 手动测试：网页登录后能读到账户数据。
8. 手动测试：提交一个最小视频任务，工作台拿回视频文件。

## 实施顺序

1. 收紧登录状态：账号数据成功返回才算已登录。
2. 修正退出登录：清空状态后不能被旧心跳恢复。
3. 增加账号数据探测：先 DOM，再页面接口。
4. 补齐后端任务存储与任务接口。
5. 接通扩展领取任务、执行任务、回报状态。
6. 接通视频文件上传回工作台。
7. 前端节点接入海外版 `seedance_web` 任务结果。
8. 做真实网页登录与最小视频生成闭环测试。

## 结论

本次不再追求“看起来已登录”。海外版链路的第一道成功标准是账号数据能返回；最终成功标准是工作台能提交任务并拿回海外版生成的视频。现有扩展桥架构保留，改动集中在海外版独立模块，避免影响国内版即梦和其他节点。
