# 海外版即梦能力对齐设计

## 背景

工作台的视频生成入口同时服务国内版即梦和海外版即梦。国内版网页/CLI 支持 `Seedance 2.0 Fast VIP`、`Seedance 2.0 VIP`、`Seedance 2.0 Fast`、`Seedance 2.0` 四个选项；海外版网页实际可操作的是普通版 `Seedance 2.0 Fast` 和 `Seedance 2.0`，并且上传视频引用时会限制上传视频总时长不能超过 15.4 秒。

这次只对海外版桥接执行层做适配，不改工作台模型下拉，也不改国内版即梦的 CLI 或网页能力。

## 已确认需求

1. 工作台模型下拉保持现状，四个模型都保留。
2. 海外版执行时如果收到 VIP 模型，自动映射成海外网页可选的普通模型：
   - `Seedance 2.0 Fast VIP` 映射为 `Seedance 2.0 Fast`
   - `Seedance 2.0 VIP` 映射为 `Seedance 2.0`
3. 国内版不做上述映射，仍按国内现有逻辑执行。
4. 海外版引用素材支持图片和视频。
5. 海外版视频引用可以有多个，但所有视频总时长不能超过 15.4 秒。
6. 海外版分辨率选择按网页实际能力执行：
   - `Seedance 2.0 Fast` 不强行选择不可用的 `1080p`
   - `Seedance 2.0` 支持网页可选的 `1080p`
7. 这次不继续改登录状态判断，不碰余额、账号数据和打包逻辑。

## 方案比较

### 方案 A：修改工作台下拉

根据国内/海外状态动态改变模型下拉。优点是 UI 看起来更贴近当前区域；缺点是这套入口国内海外共用，容易影响国内版，也会让已经保存的节点在切换区域后表现不稳定。

### 方案 B：保持下拉不动，在海外桥接层适配

工作台继续允许四个模型，海外桥接执行时把海外网页不支持的 VIP 模型映射为对应普通模型，并在提交前校验海外引用素材和分辨率。优点是改动小、国内版风险低、符合当前共用入口结构。

### 方案 C：拆分国内/海外两套视频模型入口

长期最清晰，但需要改 UI、配置、历史节点兼容和任务分流，当前改动面过大。

## 推荐方案

采用方案 B。

原因是这次目标是先让海外版真实可用，同时不破坏已经能用的国内版。模型下拉属于共用入口，不适合作为本次改动点；海外网页能力差异应放在海外桥接层处理。

## 设计

### 模型映射

在海外桥接任务构建或 preset 生成阶段增加海外专用模型规范化：

- `dreamina/seedance2.0fast_vip`、`Seedance 2.0 Fast VIP`、包含 `seedance2.0fastvip` 的值，都输出 `Seedance 2.0 Fast`
- `dreamina/seedance2.0_vip`、`Seedance 2.0 VIP`、包含 `seedance2.0vip` 的值，都输出 `Seedance 2.0`
- 非 VIP 模型维持原映射

这个映射只在海外 bridge/preset 中使用，不改变节点保存的原始 `model`。

### 分辨率

海外 bridge 构建 preset 时增加 `resolution` 字段，但只在网页实际支持时传递：

- Fast 系列：如果工作台传入 `1080p`，海外 preset 不传 `1080p`，避免网页校验失败；默认让网页保持 `720p`
- 非 Fast `Seedance 2.0`：如果工作台传入 `1080p`，海外 preset 传递 `1080p`

如果页面没有对应分辨率控件，校验不能因为未找到控件误判成整个任务失败；只有传入了可支持且页面确认失败时才报错。

### 引用素材

海外 bridge 继续把工作台的图片、视频引用转为 `referenceFiles`，传给扩展页面脚本上传。

新增视频总时长校验：

- 使用浏览器可读元数据的方式获取视频时长。
- 所有视频引用时长相加。
- 总时长大于 15.4 秒时，提交前直接失败并返回清晰错误：`海外版即梦视频引用总时长不能超过 15.4 秒`
- 无法读取某个视频时长时，不默默放行；返回清晰错误，避免网页端才弹英文错误。

### 错误处理

所有新增失败都走现有节点错误展示链路，让错误留在节点错误框里，而不是只靠短 toast。

### 测试

新增或更新单元测试覆盖：

1. 海外 bridge 把 VIP 模型映射成普通海外模型。
2. 国内/普通请求不改节点原始模型。
3. Fast 模型不向海外网页强传 `1080p`。
4. 普通 `Seedance 2.0` 允许向海外网页传 `1080p`。
5. 多个视频引用总时长超过 15.4 秒时提交失败。
6. 图片引用不参与视频时长限制。

手工验证按用户实际流程进行：从工作台打开视频节点，选择即梦视频，输入正常生成内容，提交到海外网页，观察网页是否收到正确模型、引用素材和分辨率。

## 不做内容

1. 不修改模型下拉 UI。
2. 不删除国内版 VIP 模型。
3. 不改国内版即梦 CLI。
4. 不改登录/余额判断。
5. 不打包 exe。
