# Claw Code 助手哇塞功能后续推进方案

更新时间：2026-05-27

## 1. 目标

这份文档用于把 Claw Code 助手从“能聊天、能做少量画布动作”推进到“用户一句话就能让画布变好”的产品能力。

近期重点不是做一个无限制通用智能体，而是围绕幻映画布做一组高频、低风险、可验证、可回退的智能操作。优先让用户感到：助手真的理解当前画布，能直接帮我搭节点、改 prompt、检查问题、整理结构。

| 模板化/团队复用 | 还没有把选中子图提炼成可复用模板的真实保存、再次创建入口、权限、版本和团队复用策略 |

## 3. 推进原则

1. 先做免费内部操作，再碰付费生成。
2. 低风险动作可以自动应用，但必须继续经过后端 schema 和最新 context 二次校验。
3. 高风险动作继续保留预览和强确认，例如删除、大批量修改、付费生成、文件写入、shell、外部网络。
4. 每新增一种 action，必须同时补齐后端 schema、桥接 prompt 协议、前端预览/自动应用规则、executor、测试和文档。
5. 所有会改变画布的动作都要逐步接入 undo/history。
6. “哇塞”优先来自高频体验，不来自一次性大而全能力。每个阶段都要能单独演示。

阶段二验收标准：

- “检查这个画布有什么问题”能返回 3-8 条结构化问题，并在画布上留下可删除的注释。

- 失败时能显示哪一个诊断/整理动作失败，以及下一步怎么处理。

### Skill Registry 能力方法论层（2026-05-27 新增）

状态：第一版后端注入已完成，待真实模型 live 校准。

这不是新的画布 action，也不是绕过 schema 的插件系统，而是给 Claw prompt 增加“幻映领域工作方法”的能力层。它解决的问题是：助手不能只知道哪些 action 可以调用，还要知道在幻映里什么叫做“做得好”。

已落地文件：

| 文件 | 作用 |
|---|---|
| `services/claw_skill_registry_service.py` | 加载、校验、匹配、压缩注入 skill |
| `config/assistant-skills/canvas_layout.json` | 教助手理解高质量画布整理 |
| `config/assistant-skills/storyboard_director.json` | 教助手按导演视角拆分镜 |

## 8. 暂不建议现在做的事

| 不建议 | 原因 |
|---|---|
| 一上来做通用 shell/文件智能体 | 安全边界和产品价值都不如画布能力清晰 |
| 过早自动触发付费生成 | 需要强确认、额度、审计和失败补偿 |
| 过早做团队模板库 | 先证明单项目模板提炼价值 |
| 一次性支持所有节点类型 | 先覆盖文、图、视频主链路 |
| 大改画布存储结构 | 当前 action/executor 路线已经够推进 MVP |

## 9. 判断标准

每个阶段完成时，用下面 5 个问题判断是否值得进入下一阶段：

1. 用户能不能用一句自然语言触发这个能力。
2. 助手是否真的使用了当前画布上下文，而不是泛泛回答。
3. 操作结果是否直接出现在画布上。
4. 用户是否可以撤销或安全放弃。
5. 失败时用户是否知道哪里失败、为什么失败、下一步怎么办。

只要这 5 个问题能稳定回答“是”，这个阶段就可以算产品可用。
