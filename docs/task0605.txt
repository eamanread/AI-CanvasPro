  二、本次目标范围

  本次只完成 P0/P1，不把 P2/P3 全部强塞进同一轮。

  本次必须完成：

  1. Pi 助手基础真实闭环
     - 使用设置里的文本模型，不新增单独 Pi 模型配置入口。
     - 面板可发送消息、接收流式响应、展示 delta/warning/done。
     - actions 只能来自 final message.done。
     - delta/action.proposed 不能触发画布变更。
     - Pi 只能 proposal，Huanying 负责 validate、preview、confirm、execute。
     - 不允许 Pi 获得 shell/file/browser/MCP/package 权限。

  2. story_to_video P0 标杆闭环
     - 用户输入类似“做一个 15 秒雨夜赛博追逐故事短片”时，Pi 应稳定输出 story_to_video 工作流 actions。
     - 结构必须包含：
       - 1 个 story_outline 节点。
       - 1 个 style_bible 节点。
       - 3 到 8 个 shot_script 节点。
       - 每个 shot_script 对应 1 个 shot_keyframe ai-image 节点。
       - 每个 shot_keyframe 对应 1 个 shot_video ai-video 准备节点。
     - metadata 至少支持：
       - workflowKind=story_to_video
       - workflowGroupId
       - workflowStep
       - storyDurationSec
       - shotIndex
       - shotDurationSec
       - shotTitle
       - shotPrompt
       - shotVideoPrompt
     - 文本/图片生成可 queue 或进入 pending/running。
     - 视频只创建准备节点；未强确认前绝不启动视频生成。
     - preview 和 receipt 必须明确说明“故事视频工作流”“视频生成需要确认”“当前只是准备视频节点，不是已生成视频”。

  3. 真实模型 action 稳定性治理
     - 支持真实模型常见 action 形状：
       - type/action/actionType/operation
       - nodeId/targetNodeId/id
       - nodeType/data.nodeType/data.type
       - data.metadata.workflowKind
       - root metadata
       - fenced JSON
       - JSON 前后带自然语言
     - 支持 same-batch created node id 映射。
     - 支持缺 nodeType 时从同批 create_node 或当前 canvas context 推断目标节点类型。
     - 空 create_group/connect_nodes placeholder 只能在安全 workflow batch 中 warning 忽略。
     - shell/file/browser/network/package/MCP/delete 等危险动作必须 fail closed。
     - 视频生成如果没有 videoAuthorized=true 必须 fail closed 或前端强确认拦截。
     - 每个 live 失败或模型输出异常都必须沉淀为 fixture/test，不允许只靠手改 prompt。

  4. Action preview / apply / receipt 产品化
     - preview 必须分组展示：
       - diagnostics
       - create_nodes
       - connect_nodes
       - update_nodes
       - layout
       - generation
       - workflow
       - other
     - 支持逐条勾选/跳过。
     - 支持 medium/high risk badge 或说明。
     - apply 前必须重新 validate。
     - applying 期间防重复点击。
     - apply 后 receipt 显示：
       - appliedCount
       - createdNodeIds
       - createdEdgeIds
       - updatedNodeIds
       - queuedGenerationNodeIds
       - skippedVideoGenerationNodeIds
       - warnings
       - trace/conversation/message 关联信息。
     - 部分失败时保留失败信息，不吞错误。

  5. 强确认和视频双保险
     - 高风险 action 和 ai-video generation 必须强确认。
     - 前端 preview 层要显示强确认。
     - 后端 validate 层要检查 videoAuthorized。
     - executor 层即使绕过后端也要根据目标节点类型拦截 ai-video generation。
     - 模型输出 requiresConfirmation=false 不能降低本地风险判断。
     - 文案必须区分“视频准备节点”和“启动视频生成”。

  6. 附件和 @ 引用 P1 闭环
     - 附件 store 支持 image/video/document。
     - 上传或添加附件后写入 context 时必须脱敏：
       - 不传本地绝对路径。
       - 不传 blob/data URL。
       - 不传真实 token/key/signed URL。
     - 附件 usage 至少支持：
       - style
       - character
       - composition
       - product
       - firstFrame
       - mask
       - general/reference
     - 面板需要可见附件 chip。
     - 至少实现基础 usage 选择或明确的可操作交互。
     - @ 引用至少支持把节点/附件/素材引用写入 context.references。
     - 如果完整搜索弹层来不及，至少完成一个可验证 MVP：通过 UI 或 state API 选择引用，并在请求 context 中体现。

  7. Conversation / History P1 闭环
     - 自动创建 conversation。
     - 保存 user/assistant message。
     - 保存 context snapshot。
     - 保存 pending actions / transaction。
     - 保存 receipt。
     - 保存 generation tasks。
     - 历史列表可见、可搜索、可恢复。
     - 恢复 pending actions 时不能自动执行。
     - 支持删除。
     - 支持 rename/export 的后端或 API 能力；如果 UI 未做完，需记录为 P1 剩余项。
     - 导出或 debug snapshot 不得泄露 key/token/local path/blob/data URL。

  8. Generation lifecycle P1 闭环
     - 支持 queued/running/completed/failed/cancelled。
     - 支持 idempotencyKey，防重复点击重复入队。
     - renderer 未挂载时保持 pending/queued，不直接失败。
     - 文本/图片 generation 可走真实 renderer runner 或 pending fallback。
     - 失败时进入 failed，并可记录 retry 入口或后续待办。
     - receipt/history 能看到 generation task 状态。

  9. Canvas Doctor MVP 产品化
     - context 暴露 diagnostics：
       - failedNodeIds
       - missingPromptNodeIds
       - danglingEdgeIds
       - isolatedNodeIds
       - duplicateNameGroups
       - recommendedFocusNodeIds
     - doctor 模式只允许诊断、注释、聚焦，不允许自动生成、删除、覆盖 prompt/model。
     - preview 能展示诊断类型、严重程度、节点、建议。
     - 如果能落画布，优先用 comment/source-text 注释。
     - 如果落画布未完成，必须至少做到结构化 diagnostic preview + focus_nodes 可执行。

  10. Auto Layout MVP 产品化
      - 自动整理模式只允许：
        - layout_nodes
        - move_nodes
        - create_group
        - rename_node
        - focus_nodes
        - set_viewport
      - 禁止修改 prompt/model/assets/generation。
      - 支持布局策略：
        - single_chain
        - branch_flow
        - storyboard_grid
        - asset_lane
        - problem_lane
      - story_to_video 必须使用 storyboard_grid 或等价语义布局。
      - 节点不能明显堆叠。
      - 布局动作必须可 receipt、可回归。

  11. 后端/API 数据闭环
      - `/api/v2/canvas-agent/status`
        - 使用统一文本模型配置。
        - 返回 runtime/provider/model 可用状态。
        - 不泄露 secret。
      - `/api/v2/canvas-agent/chat`
        - 保持非流式兜底。
      - `/api/v2/canvas-agent/chat/stream`
        - 返回 NDJSON。
        - final-only actions。
        - 错误 frame 友好。
      - `/api/v2/canvas-agent/actions/validate`
        - latest context validation。
        - videoAuthorized 双保险。
        - action alias repair。
        - dangerous action fail-closed。
      - `/api/v2/canvas-agent/context/preview`
        - 输出脱敏上下文预览。
      - `/api/v2/canvas-agent/conversations*`
        - 支持 list/create/get/rename/delete/export/messages/receipts/context-snapshots/transactions/generation-tasks。
      - `/api/v2/canvas-agent/generation-tasks*`
        - 支持 list/create/update
      - 所有输出都必须脱敏

  12. Live / Offline 回归
      - 必须跑 Node 单测。
      - 必须跑 Python 单测。
      - 必须跑 source preflight。
      - 必须跑 Pi offline fixture regression。
      - 必须覆盖：
        - story_to_video fixture
        - invalid delta actions do not execute
        - generation permission gate
        - history restore pending actions
        - r5 basic create/connect/layout/focus
      - 如果 8777 可用，则跑真实 8777 浏览器验收
      - 8777 验收要产出 artifact：
        - screenshot
        - console/network issue summary
        - panel state
        - graph before/after
        - receipt
        - scorecard/summary
      - 未经用户允许，不要启动、重启、停止、探测 8777
